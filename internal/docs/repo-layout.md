# repo-layout — リポジトリ構成

実装の置き場の正本（[D-35](DECISIONS.md)）。

## 構成

```text
AsterAletheia/
├─ internal/docs/        設計（仕様の正本。Git で追跡）
├─ internal/（その他）    ローカル専用（原文の保存など）
├─ docs/                 公開する利用者向けの文書
└─ modules/              自作モジュールの実装
   └─ timing/            時刻モジュール
      ├─ hdl/            FPGA の回路（SharpHdl で記述）
      ├─ host/           計算機側の記録ツール
      └─ README.md       モジュール契約の四要素（制御経路・データ経路・信頼の根拠・設計の版）
```

- モジュールは `modules/<名前>/` に一つずつ置く。今後の流星電波・全天カメラなども同じ形で並べる。
- 各モジュールの README に、モジュール契約の四要素を書く（[HARDWARE](HARDWARE.md)）。
- `hdl/` と `host/` の中の構成は、実装を始めるときに決める（実装はユーザーが行う）。

## 版

- モジュールごとにタグを付ける。形式は `<モジュール名>-vX.Y.Z`（例: `timing-v0.1.0`）。
- モジュール契約の「設計の版への参照」は、このタグ（またはコミット）とパスで示す。

## 依存

- SharpHdl は nuget.org のパッケージとして参照する（SharpHdl の方針に合わせる）。
- SharpHdl に足りない機能は、SharpHdl のリポジトリに Issue を立てて扱う。

## 分割の条件

次のどれかに当てはまったら、そのモジュールを別リポジトリに切り出すことを検討する。

- モジュール単体を使う利用者や貢献者が現れ、独立した Issue・リリースの流れが要るとき
- ビルドや CI がほかと大きく異なり、同じリポジトリでは重くなるとき
