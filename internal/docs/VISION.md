# VISION — 全体設計とスコープ構造

**AsterAletheia — Open Observatory & Reality Traceability System**

## コア・コンセプト

> **「データを保存する」のではなく、「現実世界の事象から科学的真実に至るまでの過程（証明）を保存する」**

本プロジェクトは単なる観測ソフトウェアではない。光学・電波・気象など異分野の観測を統合し、物理的な信頼の起点から論理的な証明までを一気通貫でつなぐ。その全体は二つの顔を持つ。

| 顔 | 担うこと | 主なスコープ |
|----|----------|--------------|
| **Observatory OS**（汎用・分散型の科学観測 OS） | 現実を正直に捉え、記録する | S2 / S3 / S4 / S7 |
| **Reality Traceability System**（現実のトレーサビリティ基盤） | 記録から主張を導き、証明し、発見につなぐ | S4 / S5 / S6 / S8 |

二つの顔は S4（不変の観測記録）で接する。観測は記録に終わり、証明は記録から始まる。

## 解決する課題

1. **ツールの分断:** 撮影・電波受信・軌道計算・データ整理が個別の道具に分かれ、異なる現象（例: 流星の発光と電波散乱と気象条件）を同じ時間軸で横断的に解析できない。
2. **暗黙知と再現性の欠如:** どの機材で、どの時刻精度で、どんな補正を経て結論に至ったかという文脈が論文や個人の記憶に埋もれ、第三者が厳密に追試・検証できない。
3. **研究環境の閉鎖性:** 高精度な時刻基準や自動化設備が高額かつブラックボックスで、個人や小規模グループが「科学的に信頼されるデータ」を生み出す障壁になっている。

## 3 つのパラダイムシフト（研究としての新規性）

| パラダイム | 内容 | 正本 |
|------------|------|------|
| ① 対象中心から **事象中心** へ | 「変光星用」「流星用」と縦割りにせず、すべての観測を時空間で発生したマルチモーダルな物理信号として定義し、天文学・地球物理学・電波工学・環境計測を単一のモデルで接続する | [S1](scopes/S1-ontology.md) |
| ② 物理的公理としての **検証可能な信頼の起点** | 未知の遅延や勝手な内部処理が入っていないことを、公開され検証可能な設計によって自ら担保する。根拠の弱い信号源は排除せず、根拠の強さを可視化する（[D-06](DECISIONS.md)） | [S2](scopes/S2-measurement-root-of-trust.md) |
| ③ **観測の形式手法**（天文学版 Lean × Git） | 補正項を剥がす過程を型と内容アドレス型の有向非巡回グラフで管理し、前提条件が満たされない限り科学的主張を出力できないようにする | [S5](scopes/S5-analysis-provenance.md) / [S6](scopes/S6-claim-verification.md) |

---

全体設計は、特定の実装技術・言語・規格から完全に切り離し、「概念・機能・責務のスコープ（領域）」ごとに分割して定義する。

全体は、物理世界の事象を捉える最下層から、科学的真実の証明と人間の発見を支援する最上層まで、明確に責務が分離された **8 つのスコープ** によって構成される。

各スコープの詳細は [`scopes/`](scopes/) を、統合時の判断は [DECISIONS](DECISIONS.md) を正本とする。

## 4 層で見た全体像

8 スコープを粗く束ねると 4 層になる（[D-02](DECISIONS.md)）。責務の正本は 8 スコープで、4 層は全体を一目で伝えるための見方。

```text
┌─────────────────────────────────────────────────────────────┐
│ Layer 4  知識・証明・協調網                    S6 / S7 / S8 │
│   主張の生成と自動検証・地球規模の協調観測・発見の支援      │
├─────────────────────────────────────────────────────────────┤
│ Layer 3  形式的解析                                     S5  │
│   観測の型・分野別の解析手法・系譜グラフ                    │
├─────────────────────────────────────────────────────────────┤
│ Layer 2  観測ランタイムとデータ基盤                S3 / S4  │
│   状態機械と事象駆動制御・自己完結した不変の観測記録        │
├─────────────────────────────────────────────────────────────┤
│ Layer 1  物理層                                         S2  │
│   信頼の根拠を持つ時刻・空間基準とセンサー                  │
└─────────────────────────────────────────────────────────────┘
  S1（事象・観測者・不確かさ・トレーサビリティ）は全層を貫く共通語彙
```

## スコープ間の責務境界まとめ

| スコープ | 入力されるもの | 内部で保証・変換すること | 出力されるもの |
| --- | --- | --- | --- |
| **1. 統合理念・存在論** | 現実世界のあらゆる現象 | 事象・6DoF観測者・証明の概念定義 | 全スコープ共通の概念体系（Ontology） |
| **2. 物理計測・信頼起点** | 物理現象（光・電波・環境・時間） | 時空間の不確かさ定量化・線形取得・自己校正 | 信頼の根拠と不確かさが刻印された生信号ストリーム |
| **3. ノード自律制御** | 観測計画・リアルタイム生信号 | 状態遷移・異分野トリガー連動・安全縮退制御 | 自律的な機器制御とイベント検知トリガー |
| **4. 観測記録・不変基盤** | 複数ストリーム・環境・機器状態 | マルチモーダル束ね・不変性（改ざん防止）付与 | 自己完結した不変の「観測セッション記録」 |
| **5. 形式的解析・系譜** | 不変の観測セッション記録 | 型制約による誤処理防止・段階的誤差剥離・系譜記録 | 系譜（Provenance）が保証された物理指標 |
| **6. 科学的主張・検証** | 物理指標・系譜・校正/環境記録 | 前提条件の網羅的検査・証明木の構築・自動査読 | 数学的・論理的に検証済みの「科学的主張」 |
| **7. 分散協調・立体網** | 各拠点の主張・観測セッション | 多点スケジュール配分・立体三角測量・大気差分 | 地球規模・立体空間で統合された合成観測知見 |
| **8. 人間中心の発見** | 統合知見・長期アーカイブ | 異分野相関の可視化・異常や周期のハイライト | 人間による「未知の発見」と新たな研究仮説 |

## 設計上の原則

- **技術中立:** 本設計は概念・機能・責務のみを定義する。実装技術・言語・規格は各スコープの定義が固まった後、根拠を残して選定する。
- **責務の一方向性:** 各スコープは下位スコープの出力を入力とし、上位スコープへ出力を渡す。境界は上表を正とする。
- **S1 は全スコープの共通語彙:** 事象・観測者（6DoF）・現実トレーサビリティの概念は、すべてのスコープで同じ意味で使う（[GLOSSARY](GLOSSARY.md)）。
- **不確かさは消えない:** 不確かさは起点で刻印され、変換ごとに伝播し、主張の値に必ず付く（[D-07](DECISIONS.md)）。
- **信頼は可視化する:** 信号源は排除ではなく、信頼の根拠の宣言によって区別する。主張できる範囲は根拠の強さで自動的に決まる（[D-06](DECISIONS.md)）。
- **一つのグラフ:** 不変記録・系譜・証明は、内容の要約で節点を指し合う一つの有向非巡回グラフの別の見方である（[D-11](DECISIONS.md)）。
- **証明のない結論は生まれない:** 型が操作を、証明木が結論を守る（[D-12](DECISIONS.md)）。

## 開発系譜における位置付け

これまで個別に培ってきた三つの領域を、一つの哲学の下に統合する。事象を「何が・どこで・いつ」と読むと、三つはそれぞれ一つの問いに対応する。

| 領域 | 先行プロジェクト | 問い | 主に活きるスコープ |
|------|------------------|------|--------------------|
| 信号 | AudioTrace | 何が（時間周波数で見た信号） | S2 / S5 |
| 空間 | SferaMonitor | どこで（球面・3 次元の座標、軌道、三角測量） | S1 / S7 |
| ハードウェア | SharpHdl | いつ（決定論的な回路による信頼できる時刻） | S2 |

この対応は経験の継承を示すもので、技術選定を拘束しない。
