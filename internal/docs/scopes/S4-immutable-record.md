# Scope 4：観測記録・不変データ基盤スコープ

**【役割】同時刻に得られた異種データ群と環境文脈を 1 つの単位に束ね、数十年後でも完全に再現・検証可能な形で永続化する記憶層**

「ファイルがバラバラに保存されていて当時の状況が分からない」という事態を根絶し、観測行為そのものをカプセル化して保存する領域。

| 入力 | 内部で保証・変換すること | 出力 |
|------|--------------------------|------|
| 複数ストリーム・環境・機器状態 | マルチモーダル束ね・不変性（改ざん防止）付与 | 自己完結した不変の「観測セッション記録」 |

---

## 1. マルチモーダル・セッションバンドル

- 単一の画像や波形ファイルを保存の単位とせず、「ある目的・時間帯に稼働したすべてのセンサーストリーム、空間・姿勢履歴、環境条件、機器構成、適用すべき校正データ」を 1 つの不可分なパッケージ（観測セッション）として束ねる。
- これにより、どのような観測であっても「その瞬間に周囲で何が起きていたか」という文脈が絶対に失われない。

観測セッションが概念として持つもの（保存形式は定めない）:

| 構成要素 | 内容 |
|----------|------|
| 識別 | セッション自身の識別と、属する目的（計画・プロジェクト）の識別 |
| 観測者の軌跡 | 位置・速度・姿勢と各不確かさの時系列。固定観測所は特殊ケース（[D-03](../DECISIONS.md)） |
| 時刻の文脈 | 同期している基準、推定誤差の範囲、時刻を捕捉した仕組みの状態 |
| 信号ストリーム群 | モダリティ（光学・電波・環境など）を属性に持つ生信号。各サンプルに時刻と不確かさが付く。環境のストリームも他と同じ身分の観測である（[D-20](../DECISIONS.md)） |
| 機器構成と状態 | 構成モジュールとその設計の版、観測拠点ソフトの版、機器の設定、素子温度・電源電圧など S2 が同時計測した状態（[D-19](../DECISIONS.md)） |
| 制御の文脈 | S3 の状態遷移、トリガー、品質フラグの履歴 |
| 信頼の根拠 | 各信号源が宣言した根拠と等級（S2） |
| 校正への参照 | セッション内の校正はその一部として持ち、別途取得した校正は別の観測記録として内容の要約で指す（[D-05](../DECISIONS.md)） |

系譜（派生データ）はここに含めない。理由は次節。

## 2. 生データの不変性（Immutability）と完全性証明

- 一度記録された生データおよび当時の文脈情報は、いかなる理由があっても上書き・変更を許さない「不変の事実」として扱う。
- データが生成された瞬間に暗号学的な要約（ハッシュ等）を生成し、保存や転送、あるいは気球からの回収といった物理的移動の過程で「1 ビットたりとも破損・改ざんされていないこと」を後から数学的に証明できる構造を持たせる。
- 観測セッションは **系譜グラフの根** であり、中身は二度と変わらない。派生データは、入力を内容の要約で指す新しい節点として S5 が **追記** する（[D-04](../DECISIONS.md)）。不変性と再計算可能性はこうして両立する。
- 完全性の要約の連鎖、S5 の系譜、S6 の検証は、一つの内容アドレス型グラフの別の見方である（[D-11](../DECISIONS.md)）。

## 3. オフライン完結性と遅延同期

- ネットワーク接続が全くない山間部や成層圏であっても、拠点単独で完全な記録と証明構造の構築が完結する設計とする（ローカルファースト）。
- 通信が回復した際、あるいは狭帯域の通信路しか持たない場合には、「全体の要約と証明情報」を優先して送り、大容量の生データは後から差分同期できる柔軟な永続化モデルを担う。

---

## 他スコープとの関係

- S2 のストリームと S3 の制御文脈を束ねて観測セッションにする。
- 観測セッションは S5 の唯一の入力であり、S6 のハッシュ連鎖検証の起点になる。
- 「要約と証明情報を先に送る」モデルは、S7 の段階的共有モデルと対になる。
